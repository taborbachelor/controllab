ControlLab

Virtual Commissioning & Controls Validation

Validate industrial control logic against a deterministic virtual plant. Run repeatable scenarios, inject faults, and verify safe recovery. The same scenario files run against the Python controller, the same controller over Modbus, and a real PLC runtime (OpenPLC). The question it answers: can we change this control software without breaking the machine?

What am I looking at?
  • The plant (the picture) is a simulated bulk-material line: a storage bin, a gate, a feeder, a conveyor and a hopper, with the motors, limit switches, level switches and weigh-scale a real one has. A control program runs it through the same I/O a PLC would.
  • Scenarios are the tests: a setup, operator actions, a deliberate fault, the controller behavior expected at each stage with a time limit, the recovery procedure, and a PASS/FAIL verdict with every check shown expected against actual. Run & verify runs one; on the Python runtime you watch it happen on the picture.
  • Control runtime picks what runs the plant: the Python controller, the same controller as a separate program reached only over Modbus, or OpenPLC running a Structured Text port. The scenario never changes. Compare runtimes runs one scenario on each and says how they compared.
  • Controller build can swap in a deliberately broken controller (a testing fixture, never the production code) to show a regression being caught.
  • What's happening narrates the line in plain words. Guided walkthroughs let you operate it by hand, step by step. Engineer tools break the plant manually.
  • Alarms and the event log record what the controller noticed and did.

    Instrument faults

    Stuck freezes the reading (a seized float, a frozen transmitter): nothing in the signal says it's wrong. Failed is a lost signal: WT-105 reads 0 with its channel diagnostic set; a switch reads 0, which the fail-safe level switches report as high. Try LSHH-105 stuck, then set the hopper to 97 %: WT-105 still trips the line (1oo2), and the cross-check names the switch.

    These act on the simulated equipment, never on the control program: the program has to notice and react on its own. A highlighted button is a fault currently injected; click it again to clear it. A motor trip also needs its device reset (Field resets) before the line's Reset will take, the same two-step recovery a real line has.
